# Neara RVO Boundary Fixture

Path: `tests/fixtures/neara_rvo_boundary_v0/`

## Purpose

Demonstrates Corus Kernel v0 with Neara sources: RVO as boundary subject, CVA/FDE job descriptions as artifact origins, Director as orchestrator.

## Layout

```
neara_rvo_boundary_v0/
  sources/
    sources.yaml          # source declarations
    raw/                  # raw PDFs (never parsed by derive)
  artifacts.yaml          # admitted artifacts (used by derive)
  contracts.yaml          # admitted contracts (used by derive)
  roles.yaml
  teams.yaml
  profiles.yaml
  boundaries.yaml
  moments.yaml
  timpos.yaml
  interpret_fixture.py    # Neara-specific interpret machinery (not read by derive)
  golden/
    derive.json           # golden derive output

  # generated by interpret (gitignored):
  artifacts.candidate.yaml
  contracts.candidate.yaml
  interpretation_trace.json
```

## Fixture interpreter

Neara-specific logic lives in `interpret_fixture.py`, not in the kernel. That module is test fixture machinery: it maps Neara sources to candidate artifacts and contracts. It is not a declared Corus object and is never read by `derive`.

## Workflow

```bash
# 1. Interpret sources via interpret_fixture.py → candidates
python -m corus_kernel interpret tests/fixtures/neara_rvo_boundary_v0

# 2. Review artifacts.candidate.yaml and contracts.candidate.yaml
# 3. Copy admitted objects to artifacts.yaml and contracts.yaml (already done in fixture)

# 4. Derive context
python -m corus_kernel derive tests/fixtures/neara_rvo_boundary_v0
```
